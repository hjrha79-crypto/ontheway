[작업 1: P0-2 진단 로그 모드 (Plan B)]

목적: 실제 운행 중 Accessibility 이벤트의 View 구조를 자연 수집.
    dump 대신 런타임에서 View 트리 기록.

위치: OnTheWayService.kt extractText() 또는 인접 지점

구현:
- Accessibility 이벤트 수신 시 각 AccessibilityNodeInfo 노드에 대해:
  * 깊이(depth)
  * resource-id (android:id 형태)
  * className
  * text 내용 (20자 이내 요약)
- 배민/쿠팡 패키지 이벤트일 때만 기록 (소음 방지)
- Logcat 태그: "P0_2_DIAG"
- DB 저장 NO (Logcat만). 과도한 저장 방지.

샘플 로그 형식:
P0_2_DIAG: pkg=com.woowahan.bros screen=NEW_CALL depth=3 
           id=com.woowahan.bros:id/store_name class=TextView 
           text="피나치공 장지점"

P0_2_DIAG: pkg=com.woowahan.bros screen=NEW_CALL depth=4 
           id=null class=TextView 
           text="배달료 4,990원"

빈도 제한:
- 동일 이벤트 5초 내 재발생 시 skip (로그 폭주 방지)
- 또는 신규 콜/배달 재개/완료 내역 화면에서만 기록

[작업 2: 쿠팡 재진단 로그 강화]

목적: 가설 E(초기화 타이밍) / 가설 F(재바인딩 윈도우) 확정 또는 반증.

위치: DeliveryNotificationService.kt

구현 2-A: onListenerConnected() 로그 + getActiveNotifications() 호출
---
override fun onListenerConnected() {
    super.onListenerConnected()
    Log.d("COUPANG_DBG", "onListenerConnected at ${System.currentTimeMillis()}")
    
    // 가설 F 대응: 재바인딩 시 활성 알림 복구
    try {
        val active = getActiveNotifications()
        Log.d("COUPANG_DBG", "getActiveNotifications returned ${active?.size ?: 0}")
        active?.forEach { sbn ->
            if (sbn.packageName == PKG_COUPANG) {
                Log.d("COUPANG_DBG", "Recovered coupang notification: ${sbn.id}")
                // 기존 onNotificationPosted 로직 호출
                onNotificationPosted(sbn)
            }
        }
    } catch (e: Exception) {
        Log.e("COUPANG_DBG", "getActiveNotifications failed", e)
    }
}
